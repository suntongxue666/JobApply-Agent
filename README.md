# 工作智投 · JobApply Agent

面向求职者的 Chrome 扩展。首期支持 BOSS 直聘 Web 搜索列表：读取岗位 JD、结合确认过的简历事实筛选机会、草拟个性化招呼语。纯扩展架构，无需服务器或本地后端。

**当前版本：v0.3.10。** 新增“立即沟通 → 关联新 Tab → 发送个性化招呼语 → 核验 → 关闭本次聊天 Tab → 返回搜索列表”的发送流程代码。AI 分数不再决定是否投递；标题屏蔽可开关、回车添加多个词，并按任意命中跳过。

### v0.3.10 更新

- 默认每轮最多处理 **100 个岗位**，支持在“设置 → 执行设置”中保存 1–100 的自定义上限。
- 修复旧任务点击“继续”仍受原来 10 岗上限限制的问题：继续时读取已保存的新上限，并写入当前任务。
- 保留已处理岗位、发送去重记录和原任务其他配置；修改筛选条件、简历或招呼语用于新任务。
- 到达上限后提示保存更大的上限再继续；上限不大于已处理数时明确提示，不反复恢复后立即结束。
- **155 项离线测试**、类型检查、构建与发布产物检查通过；包含旧 10 岗任务改为 25/100 后继续、记录保留和上限不足时拒绝恢复的回归验证。

v0.3.3 修正数字校验：规范空格、全角、千位符、数值和单位，支持常见中文数量；明确作为岗位名称引用的数字不当成个人资历。无法追溯时自动要求 AI 重新草拟不含量化经历的留言；第二次仍不合法则暂停，并指出具体数字，本岗不发送。岗位 JD 的数字不能作为求职者经验依据。

v0.3.1 修正后台消息来源兼容性；开聊与留言授权使用独立端口，断开与超时不重放。立即沟通按钮等待到可用再点击，发送外层等待覆盖授权与结果核验的总时长。

## 安装与更新

可直接加载的文件夹：

```text
release/工作智投-Chrome插件
```

1. 打开 `chrome://extensions`，开启“开发者模式”。
2. 初次安装：点击“加载已解压/未打包的扩展程序”，选择上述整个文件夹。它的第一层包含 `manifest.json`；不要选择 ZIP 或单个 JSON 文件。
3. 已安装旧版：点击“工作智投”的**重新加载**按钮。发布路径保持不变，无需删除扩展，原有简历与记录保留。升级后请停止旧分析任务，重新点击“开始投递”确认新的外发范围；旧版仅授权分析的任务不会自动转换成发送任务。
4. 本次新增页面脚本恢复权限和 DeepSeek 官方域名权限，如 Chrome 提示权限更新，按提示允许。新版仅使用 BOSS 与 DeepSeek 两个站点，不再声明任意 AI 域名。
5. 建议刷新已打开的 BOSS 页面，确保新状态条和“跳过”入口生效。刷新连接也会尝试恢复缺失的页面脚本。
6. 点击工具栏的绿色 `J↗` 图标打开侧栏。它与主界面左侧图标使用同一套 PNG 资源。

安装后保留发布文件夹，不要移动或删除。停用其他会操作 BOSS 的自动化扩展，再开始任务。

从 GitHub 下载的是源码，需要先按下文“开发与检查”运行 `npm ci` 和 `npm run package`，再选择生成的发布文件夹安装。Chrome 加载未打包扩展时选择整个文件夹；如果下载的是 ZIP，先解压并构建。

## 使用

### 先完成三项必填设置

侧栏顶部的“完善我的设置”放在主宣传卡片之前，每项显示“已添加 / 待设置”，可直接打开对应的全屏设置页：

| 必填项 | 完成条件 |
| --- | --- |
| 简历与事实 | 导入/粘贴简历，核对事实，勾选确认并保存 |
| 招呼语偏好 | 核对原始招呼语与语气，在对应页面保存 |
| AI 服务 | 填入并保存有效的 DeepSeek API Key；可点击连接测试确认接口可用 |

全屏设置页的这三项同时有“必填”标识。默认示例招呼语不会自动算作已设置；旧版保存过的自定义招呼语会继承完成状态。三项状态表示配置已保存，不代表模型余额或网络已通过测试。

简历支持 PDF、DOCX、TXT、Markdown，文本在本地提取，最大 10 MB；扫描 PDF 可手动粘贴文字。模型只使用用户确认过的事实。

### DeepSeek 只填 Key

当前只支持 DeepSeek 官方 API，地址和模型自动配置，设置页不再要求填写 Base URL、模型名或单独申请域名权限。模型为 `deepseek-flash`，使用非思考模式降低留言生成等待时间，依据 [DeepSeek 官方调用文档](https://api-docs.deepseek.com/) 和 [Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)。

Key 保存在本机浏览器的受信扩展存储中，不回填到输入框，不进入 BOSS 页面、日志或导出。它绑定 DeepSeek 服务域名，旧版其他服务的 Key 不会被当作 DeepSeek Key。可在设置页移除密钥。

保存并使用后，岗位 JD、脱敏简历事实、原始招呼语和表达偏好会发至 DeepSeek。连接测试只发简短测试文本，不使用简历，费用由 DeepSeek 收取。

### 连接 BOSS 与开始任务

1. 用户自行登录 BOSS 并搜索岗位。支持的执行页为 `https://www.zhipin.com/web/geek/jobs`。
2. 打开侧栏后自动检测同一 Chrome 中的 BOSS 标签页；即使当前活动页是插件设置，也能发现其他已登录的 BOSS 列表。
3. “刷新连接”显示连接中、成功或具体错误；缺少内容脚本时通过受限 `scripting` 权限补载，不要求先关闭整个浏览器。
4. 点击“开始投递”，核对本次列表、DeepSeek、规则、数量上限和外发说明，再确认。
5. 执行前会激活选定的 BOSS 标签页。切换账号、导航离开、遇到平台验证、模型错误时暂停。

“自动循环投放”默认开启：连续处理队列直到数量上限或列表结束，关闭后每处理一岗暂停。

### 每轮岗位上限与继续任务

1. 打开“设置 → 执行设置”，设置“单次最多处理岗位数（1–100）”，点击“保存设置”。默认值为 **100**。
2. 新任务使用保存的上限；已有任务点击“继续”也会读取最新保存的上限。例如旧任务已处理 10 岗，将上限保存为 100 后点击“继续”，可接着处理，整轮累计最多 100 岗。
3. 上限统计进入本轮队列的岗位，包含按规则排除、跳过等结果，不能当作成功发送数量；成功投递仅统计已核验的个性化留言。
4. 本轮已达 100 岗时，需开始新一轮；新一轮仍检查历史发送记录，避免重复发送。继续时其他配置保留原任务快照，改变筛选条件需要新建任务。

更新旧版本后，在 Chrome 扩展管理页点击“重新加载”，刷新原 BOSS 搜索列表，重新打开侧栏。如果执行设置中仍为明确保存过的 10，请手动改为 100 并保存后继续。旧版未明确配置的默认 10 会自动迁移为 100。

每个未被用户规则排除的岗位执行：

1. 点击职位卡片选择右侧详情，核对岗位 ID，读取 JD 与可见招聘者姓名；右侧详情超时仅回退到同岗位的独立详情页读取。平台验证、账号或页面变化不会触发回退。
2. DeepSeek 结合事实、原始招呼语与 JD 生成完整个性化留言；评分和匹配建议只展示，低分或 AI `reject` 不再阻止投递。
3. 保存沟通意图，创建本岗独立详情 Tab，重新核对标题、ID、正文和沟通状态；检查任务未暂停、岗位未跳过，再点击该页“立即沟通”。
4. 支持详情页内的首次沟通输入弹窗、本次详情 Tab 内跳转聊天，或由它新开的唯一子 Tab。普通聊天页核对岗位 ID、标题、公司和可读招聘者姓名；首次沟通弹窗还必须绑定本次点击的操作 ID、详情 URL/标题和唯一新输入框，不选择原有用户会话。
5. 不覆盖用户原有草稿；填入个性化招呼语后，再通过后台单次许可检查任务 epoch、Tab 和发送意图，才点击“发送”。
6. 目标会话中新出现完整留言、输入框清空且会话未改变后才记录核验成功。点击后中断或无法确定结果进入 `uncertain`，不自动重发。
7. 仅在核验成功、Tab 仍为本次聊天页且来源一致时关闭它，激活原列表继续。核验失败或页面已被用户导航则保留，不关闭其他用户页面。

开聊可能触发 BOSS 自身默认招呼语，自动流程额外发送本次个性化文案；开始确认页会说明该可能性。仅发起沟通不计个性化留言成功；不自动发送简历附件、联系方式或跟进回复。

### 职位名称屏蔽与单岗跳过

- “开始投递”下方可填写“屏蔽职位名称关键词”，与设置页“筛选与屏蔽”同一规则。
- 填入 `实习` 后，标题含“实习”的岗位在读取 JD 和调用 AI 之前直接跳过；不会误排除仅 JD 提到“实习”的其他岗位。
- 勾选“屏蔽职位名称关键词”才启用；关闭时保留已添加词，不参与该项判断。输入词后按回车变成可移除标签，可添加多个；粘贴的换行、逗号和顿号也能分词。开始时保存为本次配置快照。
- 其他规则仍包括标题包含词、指定范围排除词、公司黑名单、岗位性质、薪资区间和单岗长期屏蔽。
- 薪资金额使用“元”，不同单位不强行换算；混淆字体、面议或未知薪资进入审核或按设置跳过。

BOSS 列表的职位卡片带“工作智投”状态条：未处理、正在读取 JD、AI 分析、留言待审、规则排除、已跳过、失败或结果待核查等。DOM 异步刷新后会重新挂载，避免重复状态条。

每张可操作卡片有“跳过”按钮，侧栏岗位卡片也提供相同操作。跳过按**账号 + 当前列表 URL + 岗位 ID**保存，可在任务开始前或队列处理中使用。AI 返回的迟到结果不能覆盖“已跳过”；只中止该岗位，不停掉其他岗位。

“跳过”只作用于当前账号的该列表，与长期“屏蔽岗位 / 屏蔽公司”分开。已触发发送或待核查的岗位不能撤销成“跳过”。真实核验的发送记录优先于其他状态，才显示“投递已完成”。

## 暂停、记录与隐私

- 支持暂停、停止、继续和失败重试；跨面板执行锁防止多个任务同时操作。
- 侧栏承担队列推进，后台处理模型请求。关闭侧栏不再领取新岗位。若重新打开后仍显示旧任务运行中，先点击“恢复失联任务（先暂停）”再继续。
- 已有任务使用原配置快照，修改规则用于新任务；岗位上限例外，点击继续时读取最新保存值。旧版自定义服务任务建议停止后重新建立。
- 记录支持 CSV/JSON 导出；导出不包含 Key 和完整简历。设置页可清空本机数据。
- API 单次等待上限 20 秒，结构化输出异常最多修复一次；不静默改用固定招呼语。
- 当前账号作用域依赖页面昵称与头像的本地 hash，正式外发前还需加强身份和历史适配。
- 不处理验证码，不规避平台限制，不逆向私有接口。安全验证由用户自行完成。

提交源码、`package-lock.json`、测试、图标和文档；忽略 `node_modules/`、`dist/`、`release/`、`.preview/`、覆盖率、日志、缓存与本地密钥/环境文件。API Key、浏览器登录状态、个人简历和投递记录不应添加到源码仓库。`tests/fixtures/` 中保留合成简历供离线测试使用。

构建后的安装文件夹可通过 `npm run package` 重新生成，不作为源码提交。仓库下载者按“开发与检查”构建后加载扩展。

## 代码与设计

```text
src/
  adapters/boss/   # 列表/详情读取、沟通点击、聊天身份核对、发送与核验
  content/         # 受控页面命令、Shadow DOM 状态条、跳过
  core/            # 连接恢复、队列、规则、必填状态、隐私
  storage/         # IndexedDB、执行锁、发送意图、列表跳过与标记
  shared/          # schema、消息、DeepSeek 固定配置
  ai/              # Provider、提示词与输出校验
  resume/          # 本地文件解析
  background/      # 权限、模型、取消、新 Tab 关联、单次发送许可与关闭
  ui/              # React 侧栏、全屏设置与本地样式
public/icons/      # 工具栏/主页面共用图标
scripts/           # 构建、发布文件夹、图标和预览工具
tests/             # 离线测试、脱敏 DOM 与合成简历
docs/              # 原始目标设计、适配记录、验证与演示截图
```

PDF worker、CMap、字体和依赖均随扩展本地打包，不从 CDN 执行代码；没有遥测或自建日志服务器。原始完整目标仍保存在 [技术设计](docs/technical-design.md)，附件、多预设与缓存尚未交付；真实 BOSS 外发的生产页面兼容性仍需联调。新 Tab 关联依据 [Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs) 的创建事件和 openerTabId。
